# Website and code hardening — 2026-09-16

Status: implemented locally; not committed, pushed, or deployed. This is a
validated first hardening pass, not a claim of exhaustive repository security coverage.

## Changes

- Fixed mobile primary navigation for guests and members, nested-route highlighting,
  keyboard focus visibility, logout failure feedback, and the incorrect Geist font variable.
- Made the horizontally scrolling matchup table keyboard-accessible and named for
  assistive technology. Improved the selected History filter's text contrast and
  exposed its selected state to screen readers.
- Membership transport failures now offer retry instead of sending existing members
  to checkout. Server entitlements, not a status-only fallback, control client access.
  Account changes reset membership state. Malformed entitlement responses fail closed.
- Added session retry and cleared stale authentication errors after successful sign-in.
- Added useful global page-error and 404 recovery. Performance API failures no longer
  masquerade as empty prediction history. Billing failures have visible feedback.
- Moved the shared HTTP client into a tested module: timeout covers response bodies,
  malformed responses fail explicitly, and HTTP status survives error handling.
- Parlay percentages now have explicit units: 1% no longer renders as 100%.
  Profile changes invalidate prior results; loading disables profile switching.
- Prop analysis omits stale, future-dated, unknown-provider, and post-kickoff quotes.
  Missing history does not create a displayed projection/confidence. An opposite-side
  heuristic score is not invented by subtracting from 100. Frozen models are unchanged.
- NBA history is scoped to the current user. Legacy manual NBA grading now requires
  an internal operator. NBA performance forwards the authenticated identity, and legacy
  graded metrics are account-scoped.
- Provider exceptions no longer expose raw exception text in the affected analysis APIs.
- Upgraded Next.js 14.2.35 to patched 15.5.25, matching ESLint configuration,
  React/React DOM 19.3.0, and compatible transitive security patches.
  The PostCSS override resolves to 8.5.28, including Next's dependency.
  Applied the relevant async route-parameter migration; the Command Center re-export
  does not consume route params and needs no migration.

## Reproducing local checks

Use npm.cmd in Windows PowerShell where npm.ps1 is blocked by execution policy.

    .\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp <NEW-EMPTY-QA-PATH>
    cd frontend
    npm.cmd test
    npm.cmd run lint
    npm.cmd run build
    node node_modules/next/dist/bin/next start -H 127.0.0.1 -p 3001

In a second terminal, run __tests__/browser-hardening.cjs with:

- PLAYWRIGHT_MODULE_PATH: installed Playwright module path, if not locally resolvable.
- QA_BROWSER_PATH: installed Chromium/Edge executable, if using a system browser.
- QA_BASE_URL: optional localhost URL, default http://127.0.0.1:3001.

The browser script refuses non-local targets and mocks every API request.
Its accessibility checks use the development dependency @axe-core/playwright.
Screenshots are generated under frontend/.runtime and are ignored by Git.
Stop the local server before rebuilding.
